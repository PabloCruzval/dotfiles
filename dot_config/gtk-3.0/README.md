# GTK Theming

**Dark GTK3/4 theming powered by Noctalia v5 and `adw-gtk-theme`**

</div>

This directory configures GTK3 and GTK4 applications to use a consistent dark theme. Colors are generated dynamically by [Noctalia v5](https://docs.noctalia.dev/v5/) from the active wallpaper, while the base theme and dark-mode preference are enforced declaratively through `settings.ini` and Hyprland's autostart.

> 📝 **Note:** This `README.md` lives only in the chezmoi source repo (see `.chezmoiignore`). It is not deployed to `~/.config/gtk-3.0/`.

---

## 🎓 Tutorial: Verify GTK Theming Is Working

Follow these steps after a fresh install or theme change to confirm GTK apps are themed correctly.

1. **Install the required package:**

   ```bash
   sudo pacman -S --needed adw-gtk-theme
   ```

2. **Apply the base GTK settings:**

   ```bash
   gsettings set org.gnome.desktop.interface gtk-theme 'adw-gtk3'
   gsettings set org.gnome.desktop.interface color-scheme 'prefer-dark'
   gsettings set org.gnome.desktop.interface icon-theme 'Adwaita'
   ```

3. **Re-render Noctalia templates:**

   ```bash
   noctalia msg templates-apply
   ```

4. **Launch or restart a GTK app:**

   ```bash
   nautilus
   ```

   The file manager should open in dark mode with colors derived from the current Noctalia palette.

## 🛠️ How-to Guides

### Switch Between Light and Dark Mode

Noctalia controls the global theme mode. To toggle:

```bash
noctalia msg theme-mode-toggle
```

Then restart GTK applications (and Brave/Chromium) to pick up the change.

### Fix an App That Appears Light

Some GTK apps only read the theme at startup. Try in order:

1. Close and reopen the app.
2. Re-run the gsettings commands above.
3. Re-apply Noctalia templates:

   ```bash
   noctalia msg templates-apply
   ```

### Regenerate Colors After Changing Wallpaper

When `[theme].source = "wallpaper"`, Noctalia regenerates the palette automatically. If it does not:

```bash
noctalia msg templates-apply
```

### Manually Inspect Active GTK Settings

```bash
gsettings get org.gnome.desktop.interface gtk-theme
gsettings get org.gnome.desktop.interface color-scheme
gsettings get org.gnome.desktop.interface icon-theme
```

Expected output in dark mode:

```text
'adw-gtk3-dark'
'prefer-dark'
'Adwaita'
```

## 📖 Explanation

### How the Pieces Fit Together

The GTK theming stack has three layers:

| Layer | Source | Purpose |
|-------|--------|---------|
| **Base theme** | `adw-gtk3` (system package) | Provides the Adwaita-like GTK3/4 widgets that GTK apps render. |
| **Dark variant** | `settings.ini` + gsettings | Tells GTK to use the dark variant of `adw-gtk3`. |
| **Dynamic colors** | Noctalia v5 templates | Generates `~/.config/gtk-3.0/noctalia.css` and `~/.config/gtk-4.0/noctalia.css` with `@define-color` tokens from the active palette. |

Noctalia's built-in GTK template also writes a small `gtk.css` in each GTK config directory that imports `noctalia.css`. Because that wrapper is generated by Noctalia, it is **not** committed to chezmoi.

### Why `settings.ini` Is in Chezmoi

`settings.ini` sets the base GTK theme and the dark-mode preference. It is a static, machine-independent configuration file, so it is managed by chezmoi. The generated color files (`noctalia.css`, `gtk.css`) change whenever the wallpaper or palette changes, so they live outside version control.

### Brave and Chromium Limitation

Brave and other Chromium-based browsers read the GTK theme only at startup. They do **not** hot-reload when the theme changes. After switching from dark to light (or vice versa), you must restart the browser.

## 📚 Reference

### Managed Files

| File | Managed by | Description |
|------|------------|-------------|
| `dot_config/gtk-3.0/settings.ini` | chezmoi | GTK3 base theme, dark mode, and icon theme. |
| `dot_config/gtk-4.0/settings.ini` | chezmoi | GTK4 base theme, dark mode, and icon theme. |
| `~/.config/gtk-3.0/noctalia.css` | Noctalia v5 | Generated GTK3 color tokens. |
| `~/.config/gtk-4.0/noctalia.css` | Noctalia v5 | Generated GTK4 color tokens. |
| `~/.config/gtk-3.0/gtk.css` | Noctalia v5 | Generated wrapper that imports `noctalia.css`. |
| `~/.config/gtk-4.0/gtk.css` | Noctalia v5 | Generated wrapper that imports `noctalia.css`. |

### Settings Applied at Startup

Hyprland's `modules/autostart.lua` applies these gsettings on login:

```bash
gsettings set org.gnome.desktop.interface gtk-theme 'adw-gtk3'
gsettings set org.gnome.desktop.interface color-scheme 'prefer-dark'
gsettings set org.gnome.desktop.interface icon-theme 'Adwaita'
```

### Useful Commands

| Command | Purpose |
|---------|---------|
| `noctalia msg templates-apply` | Re-render all enabled app templates for the current palette. |
| `noctalia msg theme-mode-toggle` | Toggle between dark and light mode. |
| `gsettings set org.gnome.desktop.interface color-scheme 'prefer-dark'` | Force dark mode via dconf. |
| `gsettings set org.gnome.desktop.interface color-scheme 'prefer-light'` | Force light mode via dconf. |

## 🔧 Troubleshooting

<details>
<summary><b>Nautilus still looks light after changes</b></summary>

<br>

1. Confirm `adw-gtk-theme` is installed:

   ```bash
   ls /usr/share/themes/ | grep adw
   ```

2. Confirm gsettings:

   ```bash
   gsettings get org.gnome.desktop.interface color-scheme
   ```

3. Restart Nautilus:

   ```bash
   pkill nautilus && nautilus
   ```

</details>

<details>
<summary><b>Brave stays light after toggling theme</b></summary>

<br>

Brave reads GTK settings only at startup. Restart Brave completely.

Also verify in `brave://settings/appearance` that the theme is set to **GTK**, not forced Light or Dark.

</details>

<details>
<summary><b>Generated colors look wrong</b></summary>

<br>

1. Re-apply templates:

   ```bash
   noctalia msg templates-apply
   ```

2. Check the generated CSS:

   ```bash
   cat ~/.config/gtk-3.0/noctalia.css
   cat ~/.config/gtk-4.0/noctalia.css
   ```

3. If files are missing, verify that `gtk3` and `gtk4` are listed in Noctalia's `builtin_ids`:

   ```bash
   noctalia config export | grep -A5 builtin_ids
   ```

</details>
